Você é um engenheiro de ML sênior especializado em pipelines RAG com Python. Crie um script Python completo e funcional chamado `indexar_documentos.py` com as seguintes especificações:

**Contexto:**
Este script é a etapa de indexação de um pipeline RAG (Retrieval-Augmented Generation) para a empresa NovaTech. Os documentos são arquivos `.md` com políticas, procedimentos e SLAs corporativos. Alguns documentos possuem versões conflitantes do mesmo conteúdo (ex.: PROC-042 v1 e v2).

**Tarefa principal:**
1. Solicitar ao usuário o caminho da pasta onde estão os arquivos `.md` (input interativo via `input()`)
2. Solicitar ao usuário o caminho da pasta do ChromaDB (padrão sugerido: `./chroma_db`)
3. Ler todos os arquivos `.md` do diretório informado
4. Dividir cada documento com `RecursiveCharacterTextSplitter` (chunk_size=500, chunk_overlap=50)
5. Gerar embeddings com o modelo `all-MiniLM-L6-v2` da biblioteca `sentence-transformers` usando `SentenceTransformerEmbeddings` do LangChain
6. Armazenar os chunks no ChromaDB local na pasta informada pelo usuário

**Metadados obrigatórios por chunk:**
Extraia e armazene os seguintes metadados diretamente do conteúdo de cada arquivo `.md` (via parsing das linhas do cabeçalho):
- `source`: nome do arquivo (ex.: `PROC-042-v2-frete-especial-revisado.md`)
- `doc_id`: nome do arquivo sem extensão
- `versao`: valor extraído da linha `**Versão:**` (ex.: `2.0`)
- `data_emissao`: valor extraído da linha `**Data de emissão:**` ou `**Última atualização:**`
- `responsavel`: valor extraído da linha `**Responsável:**`
- `chunk_index`: índice sequencial do chunk dentro do documento (0, 1, 2...)
- `total_chunks`: total de chunks gerados para aquele documento

**Tratamento de versões conflitantes:**
Antes de indexar, agrupe os arquivos por `doc_id` base (ex.: `PROC-042`). Se houver múltiplos arquivos com o mesmo prefixo de ID, compare os metadados `versao` e `data_emissao`. Indexe apenas o documento mais recente; para o(s) descartado(s), registre um aviso no console indicando qual foi preterido e por quê (ex.: `[AVISO] PROC-042-frete-especial-v1.md ignorado — versão 1.0 é anterior à versão 2.0 de PROC-042-v2`). Considere `doc_id` base como os primeiros caracteres antes do segundo hífen ou padrão similar — aplique uma heurística razoável e documente no código.

**Reprocessamento (modo incremental):**
Antes de indexar cada documento, verifique se já existe no ChromaDB algum chunk com `source` igual ao nome do arquivo. Se existir, pule o arquivo e exiba: `[SKIP] arquivo.md já indexado — ignorando.` Se não existir, processe normalmente.

**Saída final obrigatória:**
Ao concluir, exiba um resumo formatado no console:

========== RESUMO DA INDEXAÇÃO ==========
Arquivos processados      : X
Arquivos ignorados (versão antiga): X
Arquivos pulados (já indexados)  : X
Total de chunks gerados   : X
Total de chunks no banco  : X
Coleção ChromaDB          : novatech_docs
Pasta do banco            : ./chroma_db
=========================================

**Requisitos técnicos:**
- Use `langchain_community.document_loaders.TextLoader` para leitura dos arquivos
- Use `langchain_text_splitters.RecursiveCharacterTextSplitter`
- Use `langchain_community.embeddings.SentenceTransformerEmbeddings`
- Use `langchain_community.vectorstores.Chroma`
- Nomeie a coleção ChromaDB como `"novatech_docs"`
- Trate erros de leitura de arquivo com `try/except` e continue para o próximo
- Use `encoding="utf-8"` na leitura dos arquivos
- Gere IDs únicos para cada chunk no formato `{doc_id}_chunk_{chunk_index}`

**Ao final, inclua um bloco comentado `# TESTE RÁPIDO` com um exemplo de consulta de similaridade para validar que o banco foi populado corretamente.**
